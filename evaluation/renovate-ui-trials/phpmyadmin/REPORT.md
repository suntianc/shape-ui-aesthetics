# phpMyAdmin UI 改造分析报告

**评级:Rebuild(重建)。** 当前界面不存在一个仍然成立的设计系统——字体、字阶、灰阶、图标语言经二十年增量叠加已经碎片化,逐项实测均无谱系可循。授权范围:视觉层整体重建,重立美学主张;信息架构(左侧库表树、浏览/结构/SQL 的功能分区)、全部功能与数据完整保留。读完本段即可决策,以下是证据。

## 证据(2026-07-26 实测,phpMyAdmin 最新 docker 镜像,浏览表界面)

**排版域**
- 字体家族未定义:计算样式首选项为 `Times` 回退裸 `sans-serif`——二十年未建立字体系统;
- 字号 8 个且无谱系:13.12px×1497 处为主力,混有 16.4 / 20.992 / 15.744 等 em 叠乘产生的碎值。参照带:内容工具字阶应为 4–6 级离散谱(语料实测 linear/asana/supabase 均如此);
- 正文 13px 是 2003 年密度标准,低于现代工具阅读带下限。

**色彩域**
- 文字灰阶失序:纯黑 #000(118 处)、#444(113 处)、#333(54 处)三种近似深灰并存,层级无定义。参照带:两级灰承载全部层级(linear 247/138 双级实测);
- 背景灰 9 级近乎连续分布(#fff #f3f3f3 #f2f2f2 #eee #ddd #d3dce3 #ccc #bbb #aaa)——评级契约"五个几乎相同的灰"条款逐字命中;
- 无强调色纪律:链接蓝、成功绿、提示黄、30+ 彩色拟物图标互相竞争,品牌橙只存在于 logo。

**信息与注意域**
- 一屏 30+ 个 16px 拟物图标(铅笔/红圈/软盘时代语言),图标承担了本应由排版层级承担的扫读工作;
- 每数据行重复"编辑/复制/删除"三组图标+文字链接,6 行数据出现 18 组相同操作;上下两套完全相同的分页控件。

**交互域**
- 原生 select 与渐变按钮混排;操作密度与点击目标尺寸不符合现代指针/触控习惯;480px 窄屏下布局崩坏(见 06 号证据截图)。

**结论**:这不是"一套过时但完整的系统"(那是 Remodel),而是系统已碎——碎值字号与连续灰阶是增量叠加无治理的直接物证。判 Rebuild。

## 改造计划(Rebuild 授权范围内)

- **重立主张**:"数据是主角,界面是工作台"——近白工作系统,版面彩度归零,数据与 SQL 用等宽字体(机器语言纪律),品牌橙精炼为唯一强调色并按槽位记账(主操作/当前位置指示/焦点);
- 字阶收敛为离散谱(数据 14px 基准);文字灰两级;背景灰收敛至 3 级;
- 图标语言:拟物森林 → 少量单色线性图标,扫读交还排版层级;
- 行操作:18 组重复链接 → 行尾悬停操作组;分页只保留一处;
- 左侧树、面包屑、全部功能标签逐一保留(信息架构在保护带内)。

**保护带(不动)**:全部功能与路由、真实数据、库表树结构、键盘可达性(重建后不低于现状)。

**风险与分期**:视觉层重建可按界面分期(浏览→结构→SQL→首页),每期独立可停;不改动任何后端与模板逻辑之外的行为。
